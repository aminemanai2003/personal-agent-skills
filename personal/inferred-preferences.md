# Inferred Preferences

These observations came from existing projects and prior work. They are provisional until confirmed in the interview.

## Engineering

- Local-first and privacy-conscious behavior.
- Narrow V1 scope with explicit non-goals.
- Strict typing, linting, tests, builds, and CI where the project supports them.
- Dependencies need a concrete justification and bounded maintenance cost.
- Public API or schema changes need compatibility tests and documentation.
- Prefer small, meaningful commits and focused pull requests.

## Data, AI, and actuarial work

- Reproducible quantitative work with documented assumptions and uncertainty.
- Avoid arbitrary composite scores and universal model rankings.
- Separate benchmark facts from interpretation.
- State domain limits instead of inflating claims.

## UI and UX

- Quiet, dense, task-focused interfaces over marketing layouts.
- Restrained blue accent; light and dark modes where appropriate.
- Modest radii, segmented controls, accessible focus, reduced motion.
- Explicit loading, empty, error, and access states.
- Avoid decorative card stacking, gradients, and generic AI visual defaults.

## Communication

- Factual, concise, natural, and limitation-aware.
- Prefer plain active language over marketing claims.
- Report verification and remaining uncertainty directly.
